Part 1 · Flows

What the person does, what the cloud does

Ten flows cover the whole product. Rounded nodes are things the person sees; rectangles are things the system does; diamonds are decisions. Each flow names the agents and the model tier that runs them.

F1 · Boot and first run

Preloader → workstream list → first workstream. The cloud is blue the whole way.

Ultra plans once, Super/Nano do the work concurrently.

F8 · Router and fallback

Per hop. Role tier is the ceiling; never falls up.
%%{init:{"theme":"base","themeVariables":{"primaryColor":"#f3eddc","primaryTextColor":"#100f0f","primaryBorderColor":"#100f0f","lineColor":"#100f0f","fontFamily":"Manrope, sans-serif","fontSize":"13px"}}}%%
flowchart TD
  A[Hop: role, brief, tools, risk] --> B{Deterministic rule hits?}
  B -- yes --> D[Tier chosen]
  B -- no --> C[Nano classifier 0–2, cached] --> D
  D --> E{Cache hit?}
  E -- yes --> F[Reuse response · usage.cached = true]
  E -- no --> G[Call Token Factory]
  G --> H{429 / 5xx / timeout?}
  H -- no --> I[route event · badge if chosen ≠ ceiling]
  H -- yes --> J[Retry once] --> K{Still failing?}
  K -- yes --> L[Fall one tier down · route.fallback = true] --> G
  K -- no --> I
  F --> I

F11 · Composer states

One box in every state. Only the placeholder, the primary button and what Enter does change, so Enter is always predictable.
%%{init:{"theme":"base","themeVariables":{"primaryColor":"#f3eddc","primaryTextColor":"#100f0f","primaryBorderColor":"#100f0f","lineColor":"#100f0f","fontFamily":"Manrope, sans-serif","fontSize":"13px"}}}%%
stateDiagram-v2
  direction LR
  [*] --> idle: 'Give the crew a goal…' · RUN
  idle --> drafting: typing or attaching a file
  drafting --> drafting: Nano estimate 400 ms after typing stops · cost pill
  drafting --> slash: text starts with / or @ · menu above the box
  slash --> drafting: pick an item or Esc
  drafting --> planning: Enter or RUN · plan card in the transcript
  planning --> idle: Cancel within 3 s
  planning --> running: 'Steer the crew…' · STEER + STOP
  running --> running: Enter queues a steering note for the orchestrator's next turn
  running --> asked: crew asks a question · 'Answer the crew…' · REPLY
  asked --> running: Enter sends the answer
  running --> waiting: approval.request · tray above the composer, cloud orange
  waiting --> running: Approve · Approve and always allow · Reject with a note
  running --> idle: run.end or STOP · run summary in the transcript
Part 2 · Dimensional sheets

How each surface is built

Eight sheets in the dimensional-drawing style: grays only, variables instead of numbers, slots instead of copy. Each sheet has notes, a plan view, details and a variable table. Scroll sideways on a phone.

Part 3 · States and color

The only places color carries meaning

The sheets are monochrome on purpose. In the app, color is reserved for agent identity, the cloud's mood, and the route badge. Everything else uses the Sorbet neutrals and the mint accent.
